# Contributing to Awesome Vaults

Thanks for helping build the best learning map for onchain vaults. This list stays useful only if every entry earns its place, so contributions are held to a high bar.

## What belongs here

A resource is a good fit when it teaches how vaults actually work: the accounting, the standards, the architecture, the security, or the production systems that use them. Think EIPs, protocol docs, reference implementations, deep-dive articles, workshops, and audit writeups.

## What does not belong here

- Price predictions, "best APY" roundups, or anything framed as an investment tip.
- SEO listicles, affiliate blogspam, and thin content that restates a standard without adding understanding.
- Marketing pages with no technical substance.
- Dead links, parked domains, or paywalled content with no free value.

## How to add a resource

1. Fork the repository and create a branch.
2. Add your entry to the most relevant section, keeping the section in a sensible order (roughly beginner to advanced).
3. Use this format:

   ```
   - [Title](https://link) - One neutral sentence describing what the reader learns. `level` `author/org`
   ```

   - Link to the original, canonical source (the author's own post, the protocol's own repo or docs), not a mirror or aggregator.
   - Write the description as a single specific sentence. State what the reader learns. No marketing adjectives.
   - Tag the level: `beginner`, `intermediate`, or `advanced`.
4. Keep entries alphabetical only where the section already is; otherwise order by learning progression.
5. Open a pull request. In the description, say why the resource is worth adding and who it helps.

## Quality checklist before you open a PR

- [ ] The link works and points to the actual resource, not a homepage.
- [ ] The resource teaches mechanism, not hype.
- [ ] It is not already covered by an existing entry.
- [ ] The description is one neutral sentence with a level tag.
- [ ] Spelling and formatting match the surrounding entries.

Removals are welcome too. If a link dies or a resource goes stale, open a PR to fix or drop it.
